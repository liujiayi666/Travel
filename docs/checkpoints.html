P0-1 理解 frontend 脚手架

  • 脚手架 = 生成器拷模板（npm create vite → create-vite 包）；Vite 双身份：dev server 按需编译秒开 / build 用 Rollup 全量打包
  • 入口是 index.html：module script → main.tsx → createRoot 把组件树挂进 #root
  • !（non-null assertion）只骗编译器不骗运行时；strict 模式下 null 不可隐式传给不收 null 的参数
  • StrictMode dev 下双渲染 = 故意暴露不纯的渲染函数（副作用），生产只跑一次
  • HMR：模块级热替换且保留组件 state，配 esbuild + 原生 ESM 构成 Vite 的快
脚手架产物每个文件各司其职：html 是壳、main.tsx 是挂载点、App 是内容；dev 与 build 是两条独立流水线。

P0-2 vite proxy + App.tsx 健康页

  • dev proxy：前端只写相对路径 /api，Vite 转发到后端端口——免 CORS、环境可移植（prod 换 Nginx，代码零改动）
  • fetch 两层状态：HTTP 层（response.ok）管传输，应用层（body.status）管业务；先查 ok 再 json()
  • fetch 只有网络层失败才 reject——404/500 都走 then，且 404 的 body 可能是合法 JSON
  • 判别联合（discriminated union）让非法状态不可表示；error = 拿不到可信答案，degraded = 后端诚实上报
  • StrictMode dev 双渲染实证：Network 面板两次请求
前后端联调走同源代理消除跨域，加载状态用判别联合建模，让 TS 编译器替你守住状态机。
